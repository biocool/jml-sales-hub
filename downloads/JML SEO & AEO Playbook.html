Setting up AI traffic tracking, step by step GA4 · PostHog · the pattern to paste
The pattern
.*(chatgpt|openai|perplexity|gemini\.google|copilot\.microsoft|claude\.ai).*

Matches visits from ChatGPT, Perplexity, Gemini, Copilot and Claude. ChatGPT also tags many of its links with utm_source=chatgpt.com, which the same pattern catches. Add new assistants to the list as they appear.

GA4
  1. Admin → Data display → Channel groups → copy the default group.
  2. Add a channel named AI assistants: Source matches regex, paste the pattern.
  3. Drag it above Referral, or Referral claims these visits first. Save.
  4. In Reports → Acquisition → Traffic acquisition, switch the table to the new channel group.
  5. Check the key events column, so we report AI leads, not just visits.
PostHog
  1. New insight → Trends → event $pageview.
  2. Filter: $referring_domain matches regex, paste the pattern.
  3. Break down by $referring_domain to see each assistant.
  4. Add a funnel from that pageview to the lead key event.
  5. Save both to the client's dashboard.

These numbers undercount. Some apps hide where a visit came from, and many people read the AI answer, then search the brand later. That's why 1.4 tracks brand demand alongside this.

Schema guide: which schema goes on which page types, examples, how we add it

Schema is a block of code (JSON-LD) that tells search engines and AI tools, in a fixed format, what a page is about: this is a plumbing business, this page is a service, this article was written by this person on this date. Each page type gets its own schema.

Page type → schema

HomepageOrganization or a LocalBusiness subtype, plus WebSitename, logo, url, telephone, address, areaServed, sameAs (profile links)Describes the business once. Every other page points back to it by its @id.
Service pageServicename, serviceType, provider (→ business @id), areaServed, offers if prices are publicOne service per page. The business type goes on the homepage, not here.
Location pageLocalBusiness subtype, one per locationaddress, geo, openingHoursSpecification, telephoneMust match the Business Profile exactly.
Blog post, guideBlogPosting or Articleheadline, author (a Person with a bio URL), datePublished, dateModified, imageThe author must be a real, named person.

How we add it
BranchWhat runs the site?
WordPressRank Math or Yoast for sitewide schema; custom JSON-LD blocks for service and location pages.
Webflow, ShopifyJSON-LD in the page template or a custom code embed per page.
Custom buildBrief the client's developers with the exact JSON-LD per template.
Rules
  • Put JSON-LD in the page HTML, not only through Tag Manager. Google can read script-added schema, but many AI crawlers don't run scripts.
  • Only mark up what a visitor can see on the page. Hidden or invented details break Google's rules.
  • Review stars: Google ignores ratings a business publishes about itself on its own Organization or LocalBusiness schema.
  • Validate every template in the Rich Results Test and the Schema Markup Validator, then watch the Enhancements reports in Search Console.

SSIndexed

Getting pages indexed: how it works and what to do when it doesn't steps, statuses, fixes
Discovered→Crawled→Indexed→Ranking

Google first has to find the URL, then visit it, then decide it's worth keeping. Only indexed pages can rank or be used in Google's AI answers. Most new pages on a healthy site are indexed within days to a few weeks.

Speed it up
  1. The page is in the XML sitemap, which updates automatically.
  2. Link to it from 3 or more pages that are already indexed (the homepage, its main service page, related posts).
  3. Request indexing once in Search Console's URL Inspection tool. There's a daily limit, so save it for important pages.
  4. Ping Bing with IndexNow (most SEO plugins do this automatically).
  5. Backlinks we've earned that Google hasn't found after 2 weeks: submit them through Indexification, so the link counts.
When a page isn't indexed: read the status
Status in the Pages reportWhat it meansWhat we do
Discovered, currently not indexedGoogle knows the URL but hasn't visited yetAdd internal links, check the site isn't slow or overloaded, wait 2 weeks
Crawled, currently not indexedGoogle visited and decided it isn't worth keeping yetUsually a quality problem: make the page more useful and less like other pages
Duplicate, Google chose a different canonicalGoogle thinks another page says the same thingMerge the pages, or make this one clearly different
Excluded by noindexThe page tells Google not to index itRemove the noindex if it should rank
Blocked by robots.txtGoogle isn't allowed to visitFix robots.txt
Page with redirect / Not found (404)The URL moved or doesn't existFix internal links to point at the final URL
Don't
  • Don't request indexing for the same URL again and again; it doesn't speed anything up.
  • Don't use Google's Indexing API for normal pages. Google allows it only for job postings and livestream videos.
  • Don't run the client's own pages through indexing services. Search Console handles those; Indexification is only for backlinks (step 5).

Not indexed after 4 weeks with good links? Treat it as a quality or duplication problem, not a technical one.

High risk Last-resort tactics (black hat) read before considering any of these
These break Google's spam policies. If Google catches them, the client can lose rankings across the whole site, through a manual action or quietly through an algorithm update. Recovery takes months and isn't guaranteed. They are a last resort, not a growth plan.
Only consider them when all of these are true
  • Every option in "Ways we earn links" has been worked for at least 6 months without enough movement.
  • The client has been told the risks in plain words and has signed a written acknowledgment.
  • The account lead and SEO lead have both approved it.
  • The client isn't in legal, medical or financial services, where losing visibility does the most harm.
  • Every step is logged so it can be undone: redirects removed, links disavowed.
